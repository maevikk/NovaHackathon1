# 04 · Гипотезы улучшений TO-BE

| ID | Проблема / риск | Проверяемая гипотеза | Меняем в модели | KPI / ожидаемое направление | Что требуется подтвердить |

| H-01 | PR-01: норматив №8 = 171 с > такта 120 с | Изменить организацию сборки или ресурс так, чтобы операция не ограничивала заданный темп | `o8.cycle_s`: **171 → 120** (вариант, НЕ подтверждённый достижимый норматив) | потенциально увеличится выпуск, сократится ожидание | Фактический CT, возможность балансировки, безопасность и качество |
| H-02 | PR-02: транспорт по 2 и логист по заявке; реальный маршрут неизвестен | Перестроить логистику без нарушения сохранности и правил | Число логистов / партия / `travel_s` после замеров | снижение ожидания / перевозок | Спагетти, время и количество рейсов, доступность персонала |
| H-03 | PR-03: риск переполнения промежуточных складов и НЗП | Внедрить понятные FIFO/супермаркет/сигнал пополнения | В будущей модели — ёмкости буферов и начальные запасы | снижение НЗП/ВПП | Реальные уровни запасов, размер партии, сроки пополнения |
| H-04 | PR-04: отсутствие доказуемых данных для решений | Стандартизировать замеры и происхождение данных | Импорт наблюдений, статус `observed` | доверие к KPI, воспроизводимость | Правила замера ФЦК, доступ к данным предприятия |

**Измеримый эффект** H-01: выполнить сравнение при одинаковых остальных настройках, сохранить JSON обоих сценариев и полученные дельты. Демонстрационная разница **не является обещанием прироста**; в реальном процессе переход на 120 с невозможен без проверенной организационной меры.

**Методика:** сначала проблемы потока и корневые причины, затем проверка способов устранения, потом целевая карта и расчёты (МУ-17, разделы 9–10). Запрещено подменять этот порядок «красивой» TO-BE схемой.
