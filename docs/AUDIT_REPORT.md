## 3. Автоматические результаты

Команда:

```bash
python -m unittest discover -s tests -v
```

**27 тестов, PASS** на проверенной версии. Проверены авторизация, запрет неавторизованных запросов, валидация DAG, обязательные маршруты, нормативные времена, финансы с `null`, расчёт и сравнение, импорт альтернативной модели, отделение информации от материальных потоков, layout invariance, согласованность такта, идентификаторы комплектов при браке, синтаксис BPMN и базовый контроль исходников.

Дополнительный браузерный smoke-test (Chromium) проверил реальный JS интерфейса и вызовы реального локального HTTP-сервера: вход, выбор разделов, движение узлов, сохранение координат через экспорт, сброс расположения, редактирование времени, получение ответов `/validate`, `/simulate`, `/compare`, импорт другой модели, работу карты на ширине 390px и отсутствие JS page errors. **PASS**. В этой среде Chromium блокирует прямой HTTP-доступ к localhost политикой администратора, поэтому браузерный тест использует Python-мост к фактическому HTTP API: это не тождественно тесту реального браузерного сетевого стека на пользовательском компьютере.

## 4. Что нельзя считать доказанным

- **Нет фактического AS-IS в терминах наблюдений ФЦК.** Нормативные секунды не заменяют хронометраж; идеальная/целевая КПСЦ ещё не прошла экспертную проверку.
- Технологические переходы между конкретными подсборками остаются реконструкцией. Зона `verification = requires_expert_confirmation` **не снимается** до подтверждения маршрута.
- Показатель `theoretical_critical_path_s` — сумма нормативов без ожидания и логистики; это **не ВПП** по МУ-17.
- Расчётное `accepted`, `throughput`, `utilization` — результаты конкретной **упрощённой имитации**, не фактическая производительность. По умолчанию `travel_s=0`, `defect_pct=0`, входные комплекты доступны в момент `t=0`; это допущения, а не наблюдения.
- У движка нет полного списания BOM, переходов при возврате на доработку, реального маршрута логиста, расстановки помещений с автоматическим пересчётом рейсов, настоящего многопользовательского хранения и промышленной IAM. Число токенов в очереди не равно измеренному НЗП.
- Нет рабочего WebGL/Three.js 3D-тура; предварительное ТЗ включает направление B — организаторы должны уточнить обязательность совмещения двух треков.
- Без полевых измерений и тестирования у организаторов нельзя обещать достоверность прогноза или отсутствие всех возможных ошибок.

## 5. Короткая ручная проверка на компьютере команды

1. Распаковать проект, запустить `python3 -m backend.server` на Mac (`py -3 -m backend.server` на Windows), открыть `http://127.0.0.1:8765/` и войти с паролем `demo2026`.
2. Открыть КПСЦ AS-IS, перетащить №8 — изменится положение, но нормативные 171 секунд и расчётный результат не должны измениться. Вернуть «Авторасположение».
3. Перейти в TO-BE, изменить №8 с 171 до 120 секунд. Интерфейс должен показать уведомление о серверном пересчёте; AS-IS остаётся 171 с.
4. В «Сценарии» нажать «Сравнить»; увидеть показатели до/после. Открыть «Параметры», попробовать неверное число работников 0 — поле должно вернуться к прежнему значению.
5. Экспортировать JSON, закрыть/заново открыть страницу, импортировать JSON; положение и параметры восстановятся внутри импортированной модели.
6. Загрузить `data/generic_example.json`; убедиться, что модель «Раскрой → Покрытие → Проверка» не содержит планировку фабрики регулятора газа.
7. Повторить основные действия на телефоне и на компьютере, где команда будет показывать проект; проверить отсутствие ошибок в консоли браузера и Python-сервере.
