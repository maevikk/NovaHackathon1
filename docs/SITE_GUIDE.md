# PROCESS LAB — как пользоваться сайтом и проверить его перед защитой

**Применимо к версии 4.1 с исправлением перетаскивания 22.11.2026.**

## Что такое это приложение

Это локальный учебный прототип **сценарного цифрового двойника**, а не система сбора фактической телеметрии. Он показывает исходную (AS-IS) модель фабрики, позволяет создать сценарий улучшения (TO-BE), меняя условия и зависимости, и вычисляет предполагаемый результат на сервере Python. Времена операций взяты из рабочих стандартов, а не из хронометража смены; конкретные маршруты, брак, логистика и итоговый эффект без наблюдений остаются предположениями.

## Запуск и сохранение

Откройте **корневую папку всего проекта** в VS Code (там, где `backend/` и `frontend/`) и в терминале запустите `python3 -m backend.server` (macOS/Linux) или `py -3 -m backend.server` (Windows). В браузере откройте `http://127.0.0.1:8765/`, пароль `demo2026`.

Если заменили JavaScript или CSS, остановите сервер `Ctrl+C`, запустите его снова и обновите страницу с очисткой кеша (`Cmd+Shift+R` на Mac, `Ctrl+Shift+R` на Windows). Не открывайте `frontend/index.html` двойным кликом: при открытии как `file://` запросы к `/api/v1/...` не будут работать.

**Важно:** изменения в браузере пока не пишутся на диск автоматически. Чтобы не потерять их после закрытия или обновления страницы, нажмите **«Экспорт JSON»** в верхней панели; в следующем сеансе используйте **«Импорт»** и выберите этот JSON. Если не экспортировали файл, при новом входе будет загружена исходная фабрика. Импорт проверяется бэкендом.

## Вкладки и смысл действий

| Раздел | Что показывает | Что проверять |
| --- | --- | --- |
| **Обзор** | Сценарный выпуск, потенциальное узкое место, нормативные циклы и источники | У показателей есть предупреждение «не факт». Картинка меняется после расчёта |
| **КПСЦ / AS-IS** | Граф исходной модели, материальные связи, информационные сигналы | Перетаскивайте блоки; топология и выпуск НЕ меняются. Исходные циклы только для чтения |
| **КПСЦ / TO-BE** | Редактируемая модель гипотезы | Перемещение блока — только внешний вид. Добавление/удаление связей и изменение цикла — меняет модель через API |
| **КПСЦ / IDEAL** | Объяснение отсутствующих данных для подтверждённой идеальной КПСЦ | Это не готовая идеальная карта: нужна отдельная диагностика по МУ-17-2023 |
| **Планировка** | Схематичное расположение рабочих мест | Это не измеренный путь логиста; настоящее время перевозки автоматически не считается по расстоянию |
| **Параметры** | Смена, спрос, запуски, логистика, нормативы операций | Проверьте такт, измените время операции и убедитесь, что интерфейс обновил результат |
| **Сценарии** | Сопоставление исходного AS-IS и изменённого TO-BE | Нажмите «Сравнить». Результат — расчётная гипотеза, не подтверждённый эффект |
| **Экономика** | Ввод цены, расходов и расчёт возможной прибыли | Пока ставки не заданы, прибыль должна быть «нет данных», а не ноль |
| **Источники** | Список документов и границы достоверности, переключение на универсальный пример | Загрузите синтетический процесс для проверки расширяемости продукта |
| **Методика** | Последовательность КПСЦ и единицы показателей | Не путайте нормативный CT, фактический CT и ВПП |

## Почему «принято 1 из 10»?

Базовый набор задаёт 20-минутную смену (1200 с), заказ 10 шт. и такт 120 с. Симуляция в исходной версии графа даёт **2 изделия, завершивших ОТК, но только 1 принятое заказчиком**: приёмка происходит только в модельные моменты каждые 120 секунд; ещё одно изделие ожидает следующего момента выдачи. Остальные запущенные комплекты не дошли до приёмки к концу модельной смены. Операция №8 по стандарту занимает 171 с, дольше такта, что создаёт потенциальное ограничение. **Это не реальный отчёт Фабрики процессов и не свидетельство девяти бракованных изделий**: исходная модель использует 0% брака, нулевое время перевозок, условный момент поступления комплектов и непроверенные технологические связи. Для достоверного результата требуются замеры и согласование модели с экспертами.

## Проверка своими руками (с чистой моделью)

1. Зайдите в **Источники** и нажмите «Базовый VENIO-C», чтобы вернуть базовую фабрику. На **Обзоре** должно быть 1/10, если параметры не меняли.
2. Перейдите в **КПСЦ** (по умолчанию AS-IS), передвиньте блок №8 мышью, перетащив его за прямоугольник. Удерживайте кнопку мыши и двигайте. Стрелки клавиатуры также работают после выбора блока; Shift+стрелка — крупный шаг. Количество принятых изделий не должно измениться.
3. Переключитесь в **TO-BE** через раскрывающийся список в шапке КПСЦ. Передвиньте блок №8 снова: ошибка предыдущей версии (работало только в AS-IS) исправлена.
4. Нажмите «Авторасположение» — карта должна вернуться в автоматическую раскладку, без изменения времени операций.
5. Откройте паспорт операции №8, задайте 120 с вместо 171 с. Программа отправляет модель на `/api/v1/validate`, затем на `/api/v1/simulate`; по исходной версии без иных изменений расчёт показывает 2/10 вместо 1/10. Появится уведомление об обновлении.
6. Откройте **Сценарии** → «Сравнить». Должны быть указаны исходный 1/10 и изменённый 2/10 — **только в рамках этой конкретной модели**. В AS-IS норматив №8 останется 171 с.
7. В **Экономике** не заполняйте финансовые ставки — прибыль не должна отображаться как число. В **Источниках** переключитесь на синтетическую модель другого предприятия — это проверка универсальности, не источник данных о VENIO-C.
8. Нажмите **«Экспорт JSON»**, убедитесь, что файл скачался, а в нём есть `kpsc_layout` после перемещения карточки (если не сбрасывали раскладку). Затем используйте «Импорт». В импортируемом файле должны сохраниться параметры и координаты.

## Проверка связи frontend ↔ backend

В браузере откройте инструменты разработчика → **Network/Сеть**. Внесите изменение времени операции. В списке запросов должны быть `POST /api/v1/validate` и `POST /api/v1/simulate` со статусом HTTP 200. При сравнении сценариев — `POST /api/v1/compare`. Если запросов нет, откройте сайт по адресу сервера, а не как локальный HTML-файл. Если сервер выдаёт ошибку, проверьте его терминал.

Автоматические тесты из корня проекта: `python3 -m unittest discover -s tests -v` (27 тестов). Если установлены Playwright + Chromium: `python3 tests/browser_smoke.py`. Этот второй скрипт проверяет настоящий Python API через браузерную среду, включая AS-IS/TO-BE, мышь, клавиатуру и сенсорное перемещение.

## Нужно ли изменять документы Самиры и Миланы?

**Из-за исправления drag-and-drop — нет.** Требование FR-14 («двигать карточки без изменения маршрута») и API-контракт `kpsc_layout` уже содержатся в документах Миланы, а материалы Самиры описывают производство и бизнес-потребности. Нормативные данные и технологические связи не менялись в этом обновлении.

Если в будущем команда изменит не интерфейс, а **бизнес-логику, формулу KPI, смысл показателя, маршруты или подтверждённые входные данные**, нужно синхронно проверить бизнес-анализ Самиры, требования и диаграммы Миланы, данные модели, backend и тесты. Одно только перемещение прямоугольника на схеме не является технологическим изменением.

## Чего ещё нет

Нет автоматического сохранения в БД, измеренного ВПП, официально подтверждённой карты реальных перемещений логиста, расчёта возврата на доработку, полноценного 3D-тура и промышленной авторизации. Эти ограничения не нужно скрывать на защите. Работу в Safari/macOS и на компьютере команды следует проверить отдельно: автоматические браузерные тесты здесь выполнялись в Chromium.
