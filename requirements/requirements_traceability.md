# Требования и трассировка PROCESS LAB

## Статус и границы

Команда выполняет направление A «Цифровой двойник предприятия». 3D-тур, WebGL-сцена, POI и связь тура с KPI исключены из объёма этой версии. Продукт — автономный локальный прототип без ERP/MES/1С. Он не собирает фактическую телеметрию с фабрики.

Статусы значений: `documented_norm` — норматив из рабочего стандарта; `observed` — значение полевого замера с датой и источником; `scenario` — параметр гипотезы; `unknown` — данных нет. В текущем демонаборе фактических замеров нет. Нулевые начальный НЗП, брак и время рейса — допущения конкретного прогона.

### Определения четырёх метрик

1. **Время цикла операции, CTн (сек/шт).** На этом этапе — сумма времён шагов рабочего стандарта одной операции. Это норматив, не полевой CT. У операции 8 CTн = 171 с/шт. Фактический CT остаётся неизвестным, пока нет как минимум двух замеров на оператора, как требует описание инфоцентра.
2. **Пропускная способность.** Мощность узла по нормативу `3600 × workers / cycle_s` (шт/ч). Пропускная способность сменного модельного выпуска — `accepted / (shift_s / 3600)` (шт/ч). Эти два показателя не взаимозаменяемы.
3. **Загрузка.** Доля доступного времени ресурса, занятая событиями модели, по FR-08. При нулевом приходе деталей загрузка может быть низкой даже у узла с самым длинным нормативом; поэтому загрузка не используется сама по себе для объявления узкого места.
4. **Стоимость.** `выручка − материалы − труд − логистика − накладные`, только если все исходные ставки заданы. Иначе результат — `insufficient_data`.

`avg_flow_s` движка — моделируемое время от старта токена до его принятия клиентом с учётом заданного сценария. Оно не называется фактическим ВПП. По МУ-17 фактическое ВПП должно включать обработку, ожидания и транспортировки критического пути; для текущей площадки эти наблюдения отсутствуют. Сумма нормативов последовательной цепочки также не называется ВПП.

## Нефункциональные требования

| ID | Требование | Критерий приёмки |
| --- | --- | --- |
| NFR-01 Адаптивность | Основные страницы доступны на телефоне, планшете и десктопе | Проверить viewport 390, 768 и 1280 CSS px: нет горизонтальной прокрутки всей страницы; основные поля и кнопки доступны, текст и единицы не обрезаны |
| NFR-02 Пересчёт | Результат соответствует последним введённым данным | После валидного изменения ответ `/simulate` отображает новые параметры и результат; после невалидного — API возвращает ошибку, прежние значения остаются |
| NFR-03 Автономность | Нет интеграций и внешней отправки демоданных | В сетевой панели при локальном сценарии нет запросов к внешним доменам; API доступен на loopback |
| NFR-04 Воспроизводимость | Одинаковые модель, seed и настройки дают одинаковый результат | Два запуска неизменённой модели дают одинаковые значения выпуска, мощности и загрузки |
| NFR-05 Демодоступ | Авторизация служит только локальному показу | Без корректного демопароля API защищённых действий отвечает 401; пароль не позиционируется как промышленная IAM |
| NFR-06 Понятность статуса | Пользователь отличает расчёт, норму и факт | На экране есть единицы измерения и маркировка «норматив», «сценарий» или «не измерено»; модельный результат не подписан как фактический |
| NFR-07 Время расчёта демомодели | Локальный прогон VENIO-C: 12 узлов, 19 связей, 10 запусков | На компьютере защиты 10 последовательных запросов `/simulate` завершаются каждый не дольше 2 с; измерять время API без времени ручного ввода. Цель относится только к демомодели и не является нагрузочной характеристикой промышленного продукта |

Порог 2 с — внутреннее целевое требование только для демонстрационного набора на компьютере защиты; он не взят из исходного ТЗ и пока не измерен. Промышленная нагрузочная цель и профиль оборудования остаются вне объёма первого этапа.
